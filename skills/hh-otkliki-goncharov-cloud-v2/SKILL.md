# Отклики на hh.ru за Гончарова Алексея Александровича (v2: с идеями для компании)

Отличие от первой версии: в каждом письме, кроме опыта и кейсов, есть абзац с предметной идеей для компании работодателя - «Посмотрел ваш сайт (группу) …, в первую очередь я бы сделал …». Для этого перед письмом нужно посмотреть сайт или группу компании (раздел «Идея для компании»). Всё остальное - как в первой версии.

Задача: пройти рекомендованные вакансии по резюме на hh.ru, отобрать подходящие, выбрать для каждой нужное резюме и отправить отклик с сопроводительным письмом. Работа идёт в облачной сессии Claude Code: браузер - headless Chromium через скрипт `scripts/hh.js` этого скилла, вход - cookies из переменной окружения `HH_COOKIES`. Claude in Chrome и инструменты javascript_tool / computer / find здесь НЕ используются.

## Подготовка (один раз в начале сессии)

- Скрипт: `node <папка скилла>/scripts/hh.js <команда>`. Рабочие файлы - в `HH_DIR` (задать `export HH_DIR=<scratchpad>/hh-run`, в каждой команде Bash заново, т.к. переменные не сохраняются между вызовами).
- `node hh.js check` - должно быть `LOGGED_IN` и список резюме. `NOT_LOGGED_IN` или ошибка `HH_COOKIES пустая` - остановиться и попросить пользователя обновить cookies hh.ru в переменной окружения `HH_COOKIES` и начать новую сессию. Значения cookies в чат никогда не выводить и не просить вставить их в чат.
- Если `hh.ru` недоступен (403 от прокси) - попросить добавить `hh.ru` в Allowed domains окружения.

Команды скрипта (вместо `window.__…` и fetch из Chrome):
- `negotiations [N]` - список откликов → `apl.json` (вместо `window.__apl`);
- `serp "<url>" <ключ>` - выдача → `serp_<ключ>.json`, печать `id|название|компания`, у совпавших с откликами - `|ОТКЛИК`. Повторный вызов с тем же ключом берёт файл, а не грузит страницу. Ключ: `head0`, `head1`, `direct0`, `target0`, `dir0`, `headall0` и т.д.;
- `vacancy <id>` - формат работы, зарплата, `applied`, описание до 1000 символов (кэшируется в `vac_<id>.txt`);
- `company <id>` - работодатель вакансии: ссылка на страницу компании на hh, сайт из карточки компании, ссылки на соцсети из вакансии и карточки, описание компании (кэш `company_<id>.txt`);
- `site <url> [ключ]` - открыть сайт компании (без cookies hh): заголовок, meta, заголовки разделов, есть ли формы и квиз, какие счётчики и виджеты стоят (Метрика, пиксель VK, Calltouch, Roistat, Jivo, Bitrix24, amoCRM, Senler), ссылки на соцсети, текст до 2500 символов; скриншот первого экрана - `HH_DIR/site.png` (кэш `site_<ключ>.txt`). `http://` скрипт сам меняет на `https://` (прокси облака пускает только HTTPS);
- `respond <id> "<начало названия резюме>" <файл письма> [--dry]` - отклик. Письмо сначала записать в файл в `HH_DIR` (через Write), в чат не выводить.

## Как определять, что отклик уже был (важно, из-за этого был бесконечный цикл)

- Перед проходом ОДИН раз загрузить https://hh.ru/applicant/negotiations (и `?page=1`, если отклики были за последние дни) и собрать список откликов только из карточек `[data-qa="negotiations-item"]`: название из `[data-qa="negotiations-item-vacancy"]` + компания из `[data-qa="negotiations-item-company"]`. Делается командой `negotiations` (сохраняет в `apl.json`).
- В карточках откликов ID вакансий НЕТ. НИКОГДА не собирать ID регуляркой `vacancy/(\d+)` по всему HTML страницы откликов: внизу страницы блок рекомендованных вакансий (`vacancy-serp__vacancy`), их ID - не отклики. Из-за этого правило остановки срабатывало ложно.
- Вакансия из выдачи считается «с откликом», если совпадают название и компания с элементом `apl.json` (в выводе `serp` такие помечены `|ОТКЛИК`) (сравнивать без регистра, название по первым 30 символам, компанию по первым 15).
- Строку «Вы откликнулись» НЕ искать в сыром HTML (`html.includes(...)`): она есть на каждой странице hh в словаре переводов и даёт ложное срабатывание. На странице вакансии признак отклика - только элемент `[data-qa="vacancy-response-link-view-topic"]` в разобранном DOM.
- Если отклик определить надёжно не удалось - не перепроверять другими способами, а идти дальше. Финальная защита - страница отклика: если там «Вы откликнулись» или кнопка «Откликнуться повторно», ничего не отправлять.

2. Правило остановки (только для трёх выдач по резюме с фильтрами, не для «директор по маркетингу» и не для общей выдачи Head): идти по выдаче сверху вниз (от новых к старым). Как только следующая по порядку вакансия - с уже отправленным откликом (помечена `|ОТКЛИК` в выводе `serp` или на странице вакансии есть `[data-qa="vacancy-response-link-view-topic"]`), проход по этой выдаче сразу закончить: дальше по странице и на следующие страницы не идти. Кроме того остановить выдачу, если на очередной странице нет ни одной подходящей по смыслу вакансии, и в любом случае не больше 5 страниц.
3. Собрать вакансии со всех пяти выдач в один список без дублей. Fetch выдачи и вакансий делать с паузой 6-9 секунд, иначе hh включает капчу.
4. Фильтр (по названию, а где неясно - по описанию):
   - формат работы - только удалённый: в «Формат работы» на странице вакансии должно быть «удалённо» (ссылки уже фильтруют, но проверять). Только офис или только гибрид - пропуск;
   - тип занятости любой: полная, частичная, проектная - всё подходит;
   - отбирать по смыслу, а не по ключевым словам: оставлять только вакансии, которые по сути работы подходят хотя бы под одно из трёх резюме (Head of Performance / директор по маркетингу / руководитель трафика; специалист по Яндекс Директ; таргетолог VK Ads / Adblogger / Telegram Ads, интернет-маркетолог с упором на платный трафик и лидогенерацию);
   - исключать по смыслу то, что под эти резюме не подходит: например основная работа - SMM и контент, маркетплейсы (WB, Ozon), Авито, продажи, PR, дизайн, разработка, работа в агентстве на клиентские проекты, медиабаинг в арбитраже, гемблинг и т.п.;
   - исключить вакансии, где уже был отклик (см. раздел «Как определять, что отклик уже был»);
   - повторно на вакансию НЕ откликаться никогда, даже если пользователь сам прислал ссылку на неё: если на странице отклика есть «Вы откликнулись» или кнопка «Откликнуться повторно», ничего не отправлять, а коротко написать в чат, что отклик на эту вакансию уже был;
   - ограничения по минимальной зарплате нет.
5. По оставшимся прочитать описание и решить:
   - пропуск, только если нужно жить в другом городе, ездить в офис или в командировки. Частичная занятость и проектная работа - не причина для пропуска;
   - отсутствие в опыте какого-то требования (GetCourse, кейсы в конкретной нише, SEO руками и т.п.) НЕ причина пропускать - откликаться, в письме опираться на близкий опыт;
   - спорные случаи решать самому по этим правилам, не спрашивая пользователя.
6. Перед письмом по каждой вакансии - посмотреть компанию и придумать идею (раздел «Идея для компании»).
   Отправка автоматическая, как в первой версии: идею и письмо не показывать в чат и не ждать одобрения, после письма сразу откликаться. Показывать письма и ждать «ок» - только если пользователь сам прямо попросил в этом запуске «не отправляй» или «дай на утверждение».
   Откликнуться сразу (технику см. ниже): не показывать в чат тексты писем и списки найденных вакансий, не спрашивать подтверждения перед отправкой, не задавать вопросов - всё решать самому по этим правилам. Капча - не причина останавливаться (см. п. 7).
7. Капча: распознать текст с картинки, прислать картинку и распознанный текст в чат, подождать 3 секунды. Если пользователь не ответил - вводить свой вариант; если ответил «ок» - тоже свой; если прислал другой текст - его. Подробно - в «Технике отклика».
8. По ходу работы писать в чат только короткие статусы без подробностей: «Резюме Head, страница 1: 20 вакансий, 6 после фильтра», «Читаю вакансию», «Смотрю сайт компании» (без названия компании и должности), «Откликаюсь» (без названия компании и резюме). Пропущенные вакансии в чат не писать. Без пояснений.
9. Итог в конце одной-двумя строками: сколько отправлено, сколько пропущено. Список компаний - кратко, без причин по каждой.

## Защита от зацикливания

- Пользоваться только командами `scripts/hh.js`; свои Playwright-скрипты писать лишь для редкого случая (вопросы работодателя), складывая их в `HH_DIR`.
- Каждую страницу выдачи загружать ОДИН раз: команда `serp` сама сохраняет её в файл и выводит все карточки коротко (`id|название до 45 симв.|компания до 15 симв.`). Повторно ту же страницу не загружать.
- Каждую вакансию читать один раз, описание выводить не длиннее 1000 символов.
- На одну и ту же проверку или технику - не больше 2 попыток. Не получилось - пропустить вакансию и идти дальше.
- Порядок строго линейный: список откликов → 5 выдач (не возвращаться к уже пройденным) → чтение кандидатов → отклики. Не начинать проход заново посреди работы.

## Выбор резюме

- руководящие роли и вилки от 100 тыс. - Head;
- упор на Директ или вилка до 60 тыс. - Директ;
- маркетолог или таргетолог на 80 тыс., в том числе онлайн-школы - Таргетолог.

hh часто подставляет другое резюме - всегда проверять выбранное.

## Идея для компании (главное в v2)

Порядок для каждой вакансии, которую решено брать:
1. `company <id>`. Сайт брать из поля `site`, если пусто - из ссылок в описании вакансии (`desc_links`), из `social`, из описания компании; если и там нет - один поиск WebSearch по названию компании и продукту из вакансии (не по ИП, а по бренду: «квест-шоу 26 площадок …»).
2. `site <url>` по сайту (главная страница; если нужно - ещё одна внутренняя страница, не больше двух загрузок на компанию). Группа ВК без входа не открывается (пустая страница «ВКонтакте»), поэтому в первую очередь смотреть сайт; группу упоминать, только если её реально удалось прочитать.
3. Если сайта нет и ничего не открылось - строить идею по описанию вакансии и карточке компании на hh, а фразу начинать «Посмотрел вашу вакансию и страницу компании на hh». Никогда не писать «посмотрел сайт», если сайт не открывался.
4. Не тратить на компанию больше 3 загрузок. Не получилось - письмо без «посмотрел сайт», но всё равно с идеей по задаче из вакансии.

Что искать на сайте (то, что видно глазами и в коде): устаревшие акции и даты, нет оффера или цены на первом экране, нет квиза или лид-формы, нет коллтрекинга или Метрики (`widgets`), одна посадочная на все аудитории, нет разделения по городам или сегментам, нет отзывов и кейсов, сезонный спрос, который ещё можно поймать (Новый год, выпускные, сезон бронирований), связь сайта с группой ВК и рассылкой.

Абзац с идеей - второй абзац письма, сразу после приветствия, перед кейсами:
- начало: «Посмотрел ваш сайт <домен>.» (или «Посмотрел вашу группу ВК» / «Посмотрел вашу вакансию и страницу компании на hh»), затем «В первую очередь я бы …»;
- 2-3 предложения, кратко и по делу, не больше 4 строк;
- только то, что реально увидел: конкретная деталь сайта (акция, раздел, форма, виджет, города, цены) + конкретное действие в каналах, которые знает Алексей (VK Ads, Директ, Telegram Ads, посевы, Adblogger, квизы, лид-формы, коллтрекинг, сквозная аналитика, CRM);
- без общих слов («провёл бы аудит», «выстроил бы стратегию», «усилил бы маркетинг»), без критики сайта в оценочных словах («у вас плохой сайт») - называть факт и что с ним сделать;
- не придумывать цифры результата («поднимет конверсию на 30%»), не выдумывать то, чего нет на сайте.

## Техника отклика (облако)

- Перед откликом: `vacancy <id>` - в `format` должно быть «удалённо», `applied: false`. Тип занятости не проверять.
- Письмо записать в файл `HH_DIR/letter_<id>.txt`, затем `respond <id> "<резюме>" <файл>`. Название резюме - начало заголовка (первые ~25 символов), например «Head of Performance Marketing», «Специалист по трафику Яндекс Директ», «Специалист по VkAds, Adblogger».
- Статусы `respond`:
  - `SENT` - отправлено;
  - `ALREADY` - отклик уже был, ничего не отправлено, коротко написать об этом;
  - `CAPTCHA` - капча не пройдена за 3 попытки или ответ не пришёл за 30 минут: остановить проход и написать итог (см. ниже);
  - `RESUME_NOT_FOUND` - один раз повторить; не вышло - пропустить вакансию;
  - `LETTER_FAIL` - один раз повторить; не вышло - пропустить;
  - `NEED_QUESTIONS` - в выводе текст формы. Написать короткий Playwright-скрипт по образцу `respond` (те же cookies и прокси): выбрать резюме, заполнить письмо и ответы по правилам («работаю на одном проекте, могу выйти сразу…»), отправить. Не больше 2 попыток, потом пропуск;
  - `NO_BUTTON` / `UNKNOWN` - посмотреть скриншот `HH_DIR/last.png` (Read), один раз повторить или пропустить.
- Первый отклик за сессию лучше сделать с `--dry` и посмотреть `last.png`: выбрано ли нужное резюме и вставлено ли письмо.
- Плашка «поменяйте видимость резюме на „Видно всем“» - игнорировать; настройки резюме не менять. «Откликнуться повторно» не нажимать никогда (скрипт это не делает).
- Пауза между любыми загрузками hh 6-9 секунд (`sleep 7` между вызовами), иначе hh включает капчу. Из облака капча вероятнее, чем из домашнего браузера.
- Капча (обычно после нажатия «Откликнуться», уже с письмом). `respond` сам не закрывает форму: сохраняет картинку в `HH_DIR/captcha.png`, пишет в `HH_DIR/captcha.log` строку `WAIT_ANSWER <id> <попытка>` и ждёт ответ в файле `HH_DIR/answer.txt` (до 30 минут). Поле ввода - `input[name="captchaText"]` (`data-qa="account-captcha-input"`).
  - Что делать: увидев `WAIT_ANSWER`, открыть `captcha.png` (Read), распознать текст, отправить картинку пользователю (SendUserFile) с распознанным текстом, подождать 3 секунды (`sleep 3`), затем записать ответ в `answer.txt`: свой вариант, если пользователь молчит или написал «ок», иначе его текст. Ничего больше в форме не трогать.
  - После ответа в `captcha.log` появится `GOT <id>`, затем `PASSED` (отклик дальше уходит сам) или `STILL` и новый `WAIT_ANSWER <id> 1` - повторить с новой картинкой. Всего до 3 попыток.
  - Если hh пишет об ограничении откликов или капча не проходит 3 раза подряд - остановиться и написать итог.
- Запуск откликов - только по одному, одно окно браузера, без параллельных процессов. Перед запуском проверить, что нет старых процессов (`ps -eo args | grep "[h]h.js respond"`); оставшийся старый процесс перехватит `answer.txt`. Удобный цикл в фоне (Bash с run_in_background), очередь в `HH_DIR/queue.txt` строками `id|название резюме`:
  ```
  while IFS='|' read -r id r; do node <скилл>/scripts/hh.js respond $id "$r" $HH_DIR/letter_$id.txt > $HH_DIR/out_$id.txt 2>&1 < /dev/null; st=$(grep -E "^(SENT|ALREADY|CAPTCHA|NEED_QUESTIONS|NO_BUTTON|RESUME_NOT_FOUND|LETTER_FAIL|UNKNOWN|ERR)" $HH_DIR/out_$id.txt | head -1 | cut -c1-80); echo "RESULT $id ${st:-NONE}" >> $HH_DIR/captcha.log; case "$st" in CAPTCHA*) break;; esac; sleep 9; done < $HH_DIR/queue.txt; echo ALLDONE >> $HH_DIR/captcha.log
  ```
  Следить за `captcha.log` через Monitor с фильтром `WAIT_ANSWER|STILL|TIMEOUT|ALLDONE|RESULT .* (CAPTCHA|ERR|NONE)`. Статус брать из `out_<id>.txt` или `status.log`, а не из последней строки вывода: ошибки Playwright многострочные.
- Экономия: скриншоты смотреть только при ошибках, не перечитывать вакансии (кэш в `vac_<id>.txt`), компании и сайты (кэш в `company_<id>.txt`, `site_<ключ>.txt`). Пауза 6-9 секунд нужна и перед `company` (он грузит две страницы hh).

## Стилистические правила (строго соблюдать)
- Вместо «—» всегда использовать «-» (дефис).
- Не использовать спецсимволы.
- Вместо «₽/мес.» всегда писать «р./мес.» (или «тыс. р.», «млн р.»).
- Максимально избегать AI-генерированного звучания текста: не использовать длинные списки с тире на каждый пункт подряд без вариативности, живой разговорный тон.
- **Никогда не писать**: «опыта нет», «скажу сразу честно», «прямого опыта... нет», «не самый точный кандидат», «не подхожу», «вероятно, не идеальный», «не соответствую», «большой разрыв», слово «фит» (вместо него — «совпадение», «подходит под задачу», «релевантно»).
- Вместо признания отсутствия опыта — сразу переходить к релевантным сильным сторонам и фактам, без извинительного тона. Решение о соответствии оставлять работодателю, не делать выводов за него.
- Если есть существенное несовпадение по масштабу/нише — просто называть факты (цифры, что есть, чего нет) нейтрально, без оценочных характеристик типа «ниже вашего уровня».

## Подбор кейсов
- Если прямого совпадения с нишей нет — использовать максимально близкий по духу кейс (например, Cargen для любой автомобильной тематики, ТДЦ №1 для медицины, «Новая Волна» для event/бронирования/запись).
